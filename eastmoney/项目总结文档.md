# 东方财富网爬虫项目总结文档

> 本项目是一个基于 Python 的东方财富网股票数据爬虫，遵循"解析层 + 数据库层"分层架构，最终将股票行情、板块信息、个股-板块关系持久化到 MySQL 数据库。

---

## 一、项目概述

### 1.1 目标

从东方财富网（push2.eastmoney.com）抓取 A 股个股的实时行情、所属板块、个股-板块关联关系，存入本地 MySQL 数据库 `spider_eastmoney`，作为后续数据分析的基础数据源。

### 1.2 技术栈

```python
from curl_cffi import requests   # 发请求（模拟浏览器 TLS 指纹，过基本反爬）
import json                      # 解析 JSONP 返回
import re                        # 正则，提取 JSONP 中的 JSON
import time, datetime, traceback # 时间处理、错误堆栈
from peewee import MySQLDatabase, Model
from peewee import AutoField, CharField, IntegerField, DecimalField
from peewee import DateField, DateTimeField, BooleanField, CompositeKey
```

主要依赖：`curl_cffi`、`lxml`（隐式）、`peewee`、`pymysql`（peewee mysql 驱动）。

## 三、数据库设计

### 3.1 总体结构

数据库名：`spider_eastmoney`，共 4 张表：

| 表名 | 作用 | 主键 | 关系定位 |
|------|------|------|----------|
| `stock_info_least` | 个股最新行情 | `stock_code`（单主键） | 字典表（按股票去重） |
| `stock_info_history` | 个股历史行情快照 | `history_date + stock_code`（联合主键） | 事实表（每日每只股票一行） |
| `sector_info` | 板块字典 | `sector_code`（单主键） | 字典表（按板块去重） |
| `stock_sector` | 个股-板块多对多关联 | `stock_code + sector_code`（联合主键） | 中间表（关系表） |

### 3.2 字段映射（来源 → 目标）

`main.py` 中 `get_stock_detail` 返回的 `stock_info_dict` 与四张表的字段对应关系如下：

| 源 dict 字段 | 目标字段（stock_info_least / history） | 备注 |
|--------------|----------------------------------------|------|
| `stock_code` | `stock_code` | 主键 |
| `stock_name` | `stock_name` | 股票名称 |
| `quote_datetime` | `update_time` | datetime 类型 |
| `quote_datetime.date()` | `history_date`（仅 history 表） | date 类型 |
| `price` | `least_price` | 最新价（元） |
| `high_price` | `high_price` | 最高价（元） |
| `low_price` | `low_price` | 最低价（元） |
| `volume_wan_hand` | `volume` | 成交量（万手） |
| `turnover_yi` | `turnover` | 成交额（亿元） |
| `total_market_yi` | `total_market` | 总市值（亿元） |
| `circulate_market_yi` | `circulate_market` | 流通市值（亿元） |
| `pe_dynamic` | `pe_dynamic` | 动态市盈率 |
| `pe_static` | `pe_static` | 静态市盈率 |
| `pe_ttm` | `pe_ttm` | 滚动市盈率 |
| `turnover_rate_percent` | `turnover_rate_percent` | 换手率（%） |

`stock_info_dict` 中的 `sector_list`（板块字典列表）映射到 `sector_info`（按 sector_code 字典化）和 `stock_sector`（中间表，存储多对多关系）。

## 四、代码模块说明

### 4.1 data_header.py 结构

文件按"数据库连接 → 模型定义 → 写入函数 → 事务入口"四段式组织：

```python
# 1. 数据库连接
db = MySQLDatabase(database='spider_eastmoney', host='localhost',
                   port=3306, user='root', password='<your_mysql_password>')

# 2. 4 个模型类（带 get_instance 工厂方法）
class Stock_Info_Least(Model): ...        # 单主键 stock_code
class Stock_Info_History(Model): ...      # 联合主键 history_date + stock_code
class Sector_Info(Model): ...             # 单主键 sector_code
class Stock_Sector(Model): ...            # 联合主键 stock_code + sector_code

# 3. 4 个 write_to_xxx 函数（存在则更新，不存在则插入）
def write_to_stock_info_least(stock_info): ...
def write_to_stock_info_history(stock_info): ...
def write_to_sector_info(sector_info): ...
def write_to_stock_sector_relationship(stock_code, sector_code): ...

# 4. 事务入口
def write_spider_data(stock_info_least, stock_info_history, sector_info_list): ...
```

### 4.2 关键设计点

**单主键 vs 联合主键**：所有 4 张表的主键都不是自增的（要么是 CharField，要么是联合主键），所以全部采用"显式 `Model.insert(...).execute()` + `Model.update(...).where(...).execute()`"的写入套路，绕开 peewee `Model.save()` 在非自增主键场景下返回 lastrowid=0 带来的误判问题。

**get_instance 工厂方法**：每个含业务字段的模型都有 `get_instance(dict)` 类方法，参数是 main.py 解析层打包好的 dict，方法内部把 dict 拆包映射到模型字段。这把"如何从 dict 变模型实例"的知识封装在 data_header.py 里，main.py 不需要知道模型字段细节。

**事务边界**：`write_spider_data` 用 `db.atomic()` 包住 4 张表的写入，任何一张表失败都回滚已写入的数据，保证 4 张表对同一只股票要么全成功要么全失败。

### 4.3 main.py 结构

```python

import json, re, datetime, time, traceback

# 2. 自有模块
from data_header import Stock_Info_Least, Stock_Info_History, Sector_Info, write_spider_data

# 3. 三个核心函数
def get_stock_sector_list(stock_code, page_size=50): ...   # 拿股票所属板块
def get_stock_detail(stock_code): ...                       # 拿单只股票全部数据
def convert_response_text_to_json(response_text): ...       # JSONP → JSON
def get_stock_list(market_tpye, page_num): ...              # 拿股票列表（分页）

# 4. 主循环
def spider_stock_data(marker_type): ...                     # 调度入口

# 5. 启动
if __name__ == '__main__':
    spider_stock_data('m:1+t:2+f:!2,m:1+t:23+f:!2')         # 测试用前 20 只
```

### 4.4 main.py 关键修改

为了让 main.py 调用 data_header.py 的入库逻辑，main.py 做了以下改动：

第一，第 8 行新增导入：

```python
from data_header import Stock_Info_Least, Stock_Info_History, Sector_Info, write_spider_data
```

第二，主循环里"先构造模型实例，再传实例入参"，而不是把 dict 直接传进去：

```python
# =========所有数据全部拿到之后，再构造模型实例==========
stock_info_least = Stock_Info_Least.get_instance(stock_info_dict)
stock_info_history = Stock_Info_History.get_instance(stock_info_dict)
sector_info_list = []
for sector_dict in stock_info_dict.get('sector_list', []):
    sector_info_list.append(Sector_Info.get_instance(sector_dict))
# ==========写入数据库（一只股票入库失败不影响后续）==========
try:
    write_spider_data(stock_info_least, stock_info_history, sector_info_list)
except Exception as e:
    print(f'写入数据库失败，跳过该股票：{stock_code=}, {e}')
    traceback.print_exc()
time.sleep(1)  # 反爬节奏：每秒一只
```

## 五、数据流转

```
API: push2.eastmoney.com/api/qt/clist/get        (股票列表，分页)
   │
   ▼
get_stock_list(market_tpye, page_num)            (main.py)
   │  返回 stock_code_list
   ▼
for stock_code in stock_code_list:               (主循环)
   │
   ├─► get_stock_detail(stock_code)              (main.py，请求个股 API)
   │     │
   │     ├─► 解析 f43~f288 行情字段               (单位换算: /100、/10000、/100000000)
   │     │
   │     └─► get_stock_sector_list(stock_code)   (main.py，请求板块 API)
   │           │
   │           ▼
   │     stock_info_dict
   │     ├── price, high_price, low_price, ...
   │     ├── quote_datetime
   │     └── sector_list: [{sector_code, sector_name}, ...]
   │
   ├─► Stock_Info_Least.get_instance(dict)       (data_header.py，构造模型实例)
   ├─► Stock_Info_History.get_instance(dict)
   ├─► for sector in sector_list:
   │     Sector_Info.get_instance(sector)
   │
   └─► write_spider_data(least, history, sectors)  (data_header.py，事务入口)
         │  db.atomic()
         ├─► write_to_stock_info_least(least)        → 表 stock_info_least
         ├─► write_to_stock_info_history(history)    → 表 stock_info_history
         └─► for sector in sectors:
               ├─► write_to_sector_info(sector)      → 表 sector_info
               └─► write_to_stock_sector_relationship(stock_code, sector_code)
                                                      → 表 stock_sector
```

## 七、调试过程中解决的问题

按时间顺序记录开发过程中遇到的关键问题及解决方式：

### 7.1 数据库名拼写错误

最初用 `spider_eastmonery`（monery，笔误），后纠正为 `spider_eastmoney`（money，正确拼写）。MySQL 错误码 1049 "Unknown database"。

### 7.2 peewee `Model.save()` 返回值误判

peewee 的 `Model.save()` 在非自增主键场景下返回的是游标 `lastrowid`（永远是 0），不是受影响行数。原代码用 `if save_result != 1: raise` 严格判定为失败，但实际上数据已成功插入。

**解决方式**：所有"插入"操作改用显式 `Model.insert(**fields).execute()`，所有"更新"操作改用显式 `Model.update(**fields).where(...).execute()`，绕开 save() 的 lastrowid 误导。

### 7.3 联合主键模型 `save()` 报 "no data to save"

`Stock_Sector`（联合主键）的 `save()` 抛 `ValueError: no data to save!`，即使构造时传了 `stock_code=..., sector_code=...`，peewee 内部 `__data__` 字典在保存时被认为是空的。

**解决方式**：同上，用 `Model.insert(...).execute()` 绕过。

### 7.4 IDE 报"未解析的引用"

main.py 导入模型类后，PyCharm/VSCode 仍报 `Stock_Info_Least`、`Stock_Info_History`、`Sector_Info` 三个名字无法解析。原因是文件被外部覆盖过，导入行被回退到只导入 `write_spider_data`。

**解决方式**：重新写导入语句；IDE 缓存刷新后标红消失。

### 7.5 触发东方财富限流

请求间隔 `time.sleep(0.2)` 过于激进（每秒 5 次），触发 WAF 突发流量风控，curl 报 56 "Connection closed abruptly"。

**解决方式**：将 `time.sleep(0.2)` 改为 `time.sleep(1)`，降低请求频率。如仍被限流，可加 `Referer` 等完整 headers 或加重试机制。

## 八、待改进点

按优先级从高到低列出：

### 8.1 main.py 缺乏重试机制（高优先级）

`get_stock_detail` 和 `get_stock_sector_list` 碰到 curl 56、28 等瞬时网络错误时直接抛异常，触发 `spider_stock_data` 顶层 try/except 退出整个 spider。建议在两个函数内部加 2-3 次重试，每次重试前 `time.sleep` 递增。

### 8.2 main.py 顶层 try/except 范围过大（高优先级）

main.py 第 280 行的 try/except 包住整个 for 循环，单只股票失败导致整个 spider 退出。建议把 try/except 移到 for 循环内部，让单只股票失败不影响后续股票。

### 8.3 请求 headers 不完整（中优先级）

main.py 的 `requests.request("GET", url, headers=headers, ...)` 只带 `User-Agent`，缺少 `Referer`、`Accept`、`Accept-Language` 等关键头部。东方财富的 API 端对"裸请求"有专门的检测层。建议参考文档第 4.4 节，把通用 headers 抽到 `config.py` 中集中管理。

### 8.4 翻页控制硬编码（中优先级）

main.py 第 262 行 `if pagee_num > 1: break` 是测试用硬编码。要全量爬取 2317 只股票（约 116 页）需要注释掉这一行，但这样没有翻页间隔控制。参考文档建议在翻页时加 `time.sleep(random.uniform(1, 1.5))`。

### 8.5 没有专门写 config.py（低优先级）

参考文档建议 3 个文件结构：`config.py`（headers/cookies）、`data_header.py`（数据库层）、`main.py`（爬虫主逻辑）。本项目目前只有后两个，headers 直接写在 main.py 里。建议把 User-Agent 等抽出来放到 `config.py` 中。

### 8.6 没有增量更新机制（低优先级）

当前 `write_to_stock_info_history` 是按 `(history_date, stock_code)` 联合主键做"存在则更新"，但 `write_to_stock_info_least` 是按 `stock_code` 覆盖式更新。如果想做"只更新当日变化字段"或者"对比昨日数据"这类增量逻辑，目前不支持。
